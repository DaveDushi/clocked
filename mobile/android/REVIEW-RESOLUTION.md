# Android review resolution

The reboot, clock and long-gap portions of this first response are superseded by `REVIEW-2-RESOLUTION.md`. The second review established that the earlier fixtures used a false platform premise. This file preserves the earlier response; `README.md` describes current behavior.

Response to `REVIEW.md`. The original independent report is preserved unchanged. No subagents or commits were used for this follow-up.

## Resolved

- **H1:** Removed the 24-hour cursor and open-span reset. The production `CollectionPolicy.collect` queries the entire cursor-to-end gap, including any older events the OS still returns. A gap over 96 hours invalidates only stale carried activity/gates, not the returned event history. Replay tests retain two hours of work after a 30-hour gap and recover fully gated events returned after a 120-hour gap.
- **H2:** Boot, clock and timezone broadcasts collect instead of resetting. Reboot reads the persisted cursor through shutdown/startup. Secure startup requires unlock evidence; a currently unlocked non-secure device handles startup without a keyguard-hidden event. Small clock corrections keep state. Large corrections preserve closed time up to the trustworthy old-clock boundary and restore current activity through replay, with a persistent uncertainty notice. A backward clock on reboot cannot leave the collector waiting indefinitely behind an old future checkpoint. Timezone changes split metadata without dropping UTC time or an open visit.
- **H3:** Selection changes persist timestamped history. The collector processes delayed events with their historical selection, including a PAUSE inside the one-minute tail. The cursor and open visit are retained. Tests recover a two-hour visit when selection changes immediately after the PAUSE, and begin counting an already resumed app at its selection boundary.
- **M1:** Account/permission/large-clock boundaries rebuild current resumed activity through event replay and anchor any new open span at the new boundary. Replay exports no old authorization time. Small corrections, timezone changes and selection changes no longer clear activity at all. Recovery needs retained resume evidence; the app cannot identify an activity absent from the platform history.
- **M2:** `SyncEngine` captures an immutable batch and credential epoch, rechecks before nonblocking initiation, releases the vault lock for all network waiting, then checks the epoch again before ACK or status writes. An old in-flight request can finish for its captured old account but never acknowledges the new queue. Tests switch accounts while the request waits and between capture/initiation. OkHttp has call/connect/write/read limits and a separate finite caller deadline. A test with blocked DNS verifies that the caller still returns. Broadcasts never wait for HTTP.
- **M3:** Credential changes and disconnect show pending session count, union duration, open-span loss, and an in-flight-request warning, with a sync-first option. Consent is checked against the account epoch and pending IDs; newly collected unsynced work forces another review. Invalid server/token input does not clear the token field.
- **M5:** UI and README identify the current-profile scope. Work-profile users must install and authorize Clocked separately inside that profile, subject to administrator policy. A personal copy does not select the work-profile package.
- **L1:** Usage settings retries without the package URI. Both settings attempts and browser launch catch unavailable or forbidden activities and display an error.
- **L2:** `MODE_DEFAULT` uses the manifest grant. Other denied modes remain denied. Covered by a production permission-decision test.
- **L3, ordering:** The AppOps listener captures the observed permission state and timestamp, then processes callbacks on one serial executor. Every collection also checks live permission before and after event queries. Application initialization registers the listener for every newly created process, including Activity launches.
- **L4:** User-initiated sync and connection saves replace one-time work in backoff. Background triggers retain unique work.
- **L5:** UI/docs call the 60 seconds an app-chosen safety margin, describe retention honestly, and remove the old 24-hour-loss behavior. A separately persisted `boundaryNotice` survives successful sync status updates. Shutdown recovery is now reached by production collection tests.
- **L6:** Entire app rows are checkbox-role toggle targets with a minimum height and child text labels. The checkbox is passive inside the labeled row.
- **L7, practical fixes:** Unaccepted sent rows rotate behind later pending rows without changing IDs. Server origin defaults to the hosted origin. Token validation preserves input. Unreadable-vault UI links to Android's app settings. CI actions are pinned to the resolved upstream commit SHAs instead of mutable major tags.

The shallow selection-reset helper test was removed. Its replacement drives the production collection transaction, not a manually reconstructed reset. Existing union, DST, exact payload privacy and stable-ID tests remain.

## Deferred with reasons

- **M4, missing activity/task identity:** Public usage events expose package/class and lifecycle/gate events, but no trustworthy public task-area identifier. Evicting selected activity on every unrelated resume breaks valid multi-resume split-screen. No synthetic task identity or arbitrary work-duration cap was added. A missing close can overcount until a matching close, screen, keyguard or shutdown gate; missing retained starts can undercount. The README and UI disclose this. A test explicitly preserves selected split-screen work when an unrelated app resumes. Killing an app on a physical device remains a required OEM check.
- **L3, unobserved permission history:** A revoke-and-regrant entirely while the process is dead has no recoverable journal in the APIs used here. Serial live callbacks cannot establish facts about that unobserved period. This remains documented rather than claimed solved.
- **Clock discontinuity ambiguity:** Wall-clock event timestamps can collide or be remapped across a correction. Closed intervals in the trustworthy old range and queued data survive. The app does not infer a duration across the uncertain correction. Backward corrections can leave otherwise plausible later old-clock events ambiguous; the persistent notice describes that boundary.
- **L7, large-vault write cost:** Encrypted atomic whole-file writes remain. Changing storage architecture is not needed to resolve the reported losses. Very large queues increase local I/O cost, as documented. A future measured storage change must preserve the atomic checkpoint/queue guarantee.
- **L7, unreadable-vault deletion:** The app links to system app settings rather than offering an unverified direct purge of unreadable data. Android's Clear storage supplies the platform confirmation and intentionally discards the unrecoverable queue.
- **Physical device and hosted CI execution:** No phone or emulator is available, and no commit was authorized to run GitHub Actions. Permission UI, TalkBack, OEM event delivery, work profiles, real reboot/clock broadcasts, Keystore and live uploads still need device checks. Headless build, lint, deterministic collection and transport tests are recorded in `VERIFICATION.md`.
